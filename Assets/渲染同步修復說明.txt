===============================================
渲染同步問題修復說明
===============================================

問題描述：
1. Host 擊殺 Client 後，Client 重生後看不見 Host
2. Client 雖然看不到 Host，但能射中對方
3. 雙方都重生一次後，能看到移動但看不到槍和子彈

===============================================
已實施的修復
===============================================

1. 【渲染器緩存系統】
   - 添加了 cachedRenderers 列表來追蹤所有渲染器
   - 在啟動和網絡生成時緩存渲染器
   - 死亡/重生時使用緩存列表來精確控制渲染器

2. 【改進的重生邏輯】
   - RespawnClientRpc 重新緩存渲染器（確保最新狀態）
   - 添加延遲一幀的檢查（EnsureRenderersEnabledCoroutine）
   - 確保所有客戶端都執行相同的渲染器啟用操作

3. 【子彈渲染修復】
   - 在子彈的 OnNetworkSpawn 中強制啟用渲染器
   - 確保子彈在所有客戶端都可見

4. 【詳細的調試日誌】
   - 記錄每個步驟的渲染器狀態
   - 區分服務器和客戶端的日誌
   - 顯示啟用/禁用的渲染器數量

5. 【調試輔助工具】
   - NetworkDebugHelper.cs 提供實時調試功能
   - F1: 檢查所有玩家的渲染器狀態
   - F2: 強制啟用所有渲染器

===============================================
設置步驟
===============================================

1. 【檢查 Player Prefab 設置】
   確保 Player Prefab 有以下組件：
   ✓ NetworkObject (Spawn With Observers = true)
   ✓ NetworkTransform (Synchronize Position = true)
   ✓ NetworkPlayerController 腳本
   ✓ 所有 SpriteRenderer 組件（玩家、槍等）

2. 【添加調試工具（可選但推薦）】
   a. 在場景中創建空物件，命名為 "NetworkDebugHelper"
   b. 將 NetworkDebugHelper.cs 腳本掛載上去
   c. 運行時按 F1 檢查狀態，F2 強制修復

3. 【設置重生點】
   a. 創建空物件作為重生點
   b. 設置 Tag 為 "Respawn"
   c. 放在合適的位置

4. 【檢查網絡設置】
   確保 NetworkManager 正確配置：
   ✓ Player Prefab 已設置
   ✓ Network Transport 正確配置

===============================================
測試步驟
===============================================

【基本測試流程】
1. Start Host
2. Start Client (在另一個執行檔或編輯器中)
3. Host 射擊 Client 直到死亡
4. 觀察 Console，應該看到：
   - [Server] 玩家 X 死亡
   - [Client] HandleDeath: 禁用 N 個渲染器
   - [Server] 開始重生玩家 X
   - [Client] RespawnClientRpc: 啟用 N 個渲染器
5. 等待 3 秒重生
6. 檢查雙方是否能看到對方（包括玩家、槍、移動）

【進階測試】
1. 按 F1 查看所有玩家的渲染器狀態
2. 如果有渲染器顯示為禁用，按 F2 強制啟用
3. 重複測試，輪流擊殺對方

===============================================
常見問題排除
===============================================

問題1：重生後仍然看不見對方
解決方案：
- 按 F1 檢查渲染器狀態
- 按 F2 強制啟用所有渲染器
- 檢查 Console 日誌，確認 RespawnClientRpc 被執行
- 確認 NetworkTransform 正在同步位置

問題2：能看到移動但看不到槍
解決方案：
- 檢查槍物件是否是 Player 的子物件
- 確認槍物件有 SpriteRenderer 組件
- 按 F1 查看哪些渲染器被禁用
- 槍的渲染器可能需要單獨處理

問題3：看不到子彈
解決方案：
- 確認子彈 Prefab 有 SpriteRenderer
- 確認子彈 Prefab 有 NetworkObject
- 檢查子彈的 OnNetworkSpawn 是否執行
- 在子彈生成時添加日誌：Debug.Log("子彈生成")

問題4：Scene 視圖正常但 Game 視圖異常
解決方案：
- 這是典型的網絡同步問題
- Scene 視圖顯示服務器權威狀態
- Game 視圖顯示客戶端接收到的狀態
- 確保 ClientRpc 正確執行

問題5：第一次重生有問題，第二次正常
解決方案：
- 可能是渲染器緩存時機問題
- 已通過重新緩存渲染器解決
- 如果仍有問題，增加 respawnDelay 到 5 秒

===============================================
手動修復步驟（如果自動修復無效）
===============================================

如果重生後看不見對方，在運行時：

1. 打開 Console
2. 按 F1 查看狀態
3. 查找類似這樣的輸出：
   "玩家 1 (遠端玩家, 存活): 啟用渲染器 0, 禁用渲染器 5"
4. 按 F2 強制啟用
5. 再按 F1 確認修復

===============================================
代碼層面的改進建議
===============================================

如果問題持續，可以考慮：

1. 【使用 NetworkVariable 控制可見性】
   private NetworkVariable<bool> isVisible = new NetworkVariable<bool>(true);
   
   監聽變化並控制渲染器

2. 【分離玩家和槍的渲染控制】
   不要一次性控制所有子物件的渲染器
   分別管理玩家身體和武器的渲染

3. 【使用 SetActive 代替禁用渲染器】
   死亡時：graphicsTransform.gameObject.SetActive(false);
   重生時：graphicsTransform.gameObject.SetActive(true);
   
   但注意這可能影響其他組件

4. 【增加網絡同步頻率】
   在 NetworkTransform 中增加同步頻率

===============================================
性能優化建議
===============================================

當前實現會在重生時：
- 緩存所有渲染器（一次性操作）
- 啟用/禁用所有渲染器（O(n) 操作）
- 延遲一幀再次檢查（確保同步）

對於性能敏感的項目：
- 考慮只緩存關鍵渲染器
- 使用對象池來重用玩家對象
- 避免頻繁的 GetComponentsInChildren 調用
